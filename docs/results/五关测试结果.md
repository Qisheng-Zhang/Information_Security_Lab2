## 第 1 关：基础算法与 GUI

- PDF 表 D.1 的正、逆 S 盒逐项核对通过；轮常量为 80、30。
- PDF D.3：`2D55 → BCE9 → A34A`。
- PDF D.2 各变换：`A749 XOR 2D55 = 8A1C → NS 604C → SR 6C40 → MC 3743`。
- 项目回归向量（不是该 PDF 中的完整加密算例）：P=6F6B，K=A73B，C=0738，解密=6F6B。
- 10000 组固定随机种子加解密往返通过；固定密钥 2D55 下全部 65536 个明文输出无重复。
- GUI 操作记录见 [gui_smoke.json](gui_smoke.json)；15 张实际桌面截图及操作步骤见 [截图说明](../截图说明.md)。

## 第 2 关：交叉测试

Python / 独立 C++：1005 组全部通过。详见 `cross_check.md`、`cross_check.csv`。
另一小组的现场验证尚需组员交换向量并填写记录模板，不能以本机自检替代。

## 第 3 关：ASCII 字符串

- 原文：`Hello, S-AES!`，13 字节，7 个两字节分组。
- 密文分组：`2B91 7F2D 7CBD BBB5 2F04 658A 472C`。
- 原始密文字节转义显示：`+\x91\x7F-|\xBD\xBB\xB5/\x04e\x8AG,`。
- JSON 导出再导入后还原：`Hello, S-AES!`。
- 空串、奇数长度、尾部空字节、换行都通过；非 ASCII 输入被拒绝。示例包：`ascii_cipher.json`。

## 第 4 关：多重加密与中间相遇

| 模式 | 密钥 | 明文 | 密文 | 解密 |
|---|---|---|---|---|
| 双重 EE / 32 bit | 1F2E3D4C | 6F6B | FE80 | 6F6B |
| 三重 EEE / 48 bit | 1F2E3D4C5A6B | 6F6B | 5AF9 | 6F6B |
| 三重 EEE / 32 bit，K1-K2-K1 | 1F2E3D4C | 6F6B | FF78 | 6F6B |

攻击已知对：(6F6B,FE80), (1234,69D8), (BEEF,093D)。

完整枚举 K1、K2 各 65536 个值：单对得到 65423 个候选并保留真密钥；
使用三对后得到 `['1F2E3D4C']`，唯一候选为预设密钥。
上述两次攻击合计 0.953 秒。相互矛盾的已知对返回零候选；取消操作测试通过。
48 bit 前导零密钥显式按 48 bit 处理，相关用例通过。

## 第 5 关：CBC 与篡改

K=A73B，IV=1357，消息为 `Hello, S-AES CBC mode!`。

密文：`84A5 D154 0B0C F821 14B7 5C5C 868D 9D22 AF0B 1E84 FD4E`。

原文：`Hello, S-AES CBC mode!`。

| P4 | 2053 | 2053 | 0000 |

篡改后字节：`\x88ilmo, S-AES CBC mode!`。

P1 受非线性解密影响，P2 对应位翻转，P3 起相同。这里的“扰乱”不表示每一位必然翻转。

| P1 | 4865 | 4865 | 0000 |

P3 的 XOR 差值等于 C2 的替换差值 D154，P4 起不受影响。
空消息、任意位置翻转、替换分组、更改 IV 的传播边界均有自动测试。示例包：`cbc_cipher.json`。
CBC 本身不能认证密文，能观察到错误不等于能可靠检测所有篡改。
