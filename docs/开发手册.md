# 开发手册与接口

## 1. 模块边界

核心与命令行使用 Python 3.10+ 标准库，可在无桌面环境运行。GUI 使用 PySide6 / Qt Widgets，依赖锁定在 requirements.txt；视觉布局与交互逻辑分开：

| 模块 | 职责 |
|---|---|
| `core.py` | 参数、有限域、状态变换、密钥扩展、单分组加解密及逐轮记录 |
| `encoding.py` | 16/32/48 bit 输入、ASCII 和字节分组转换、保真转义显示 |
| `multiple.py` | 明确位宽的组合密钥、双重与三重加解密 |
| `modes.py` | 独立分组 ECB、CBC、JSON 密文包及 IV |
| `attacks.py` | 完整中间相遇搜索、碰撞保留、进度和取消 |
| `qt_gui.py` | Qt 事件回调、导入导出、后台任务状态 |
| `qt_ui.py` | 导航、卡片、矢量图标、状态矩阵和页面布局，不实现密码算法 |
| `gui.py` | 兼容导入入口，转向 Qt 工作台 |
| `__main__.py` | argparse 分组命令行接口 |

命名采用 snake_case，类名采用 PascalCase。核心使用不可变 tuple 和 dataclass 描述结构；函数只对传入数据运算，不修改外部全局状态。

## 2. 核心接口

所有整数参数按无符号位宽校验；错误时抛出 `ValueError`，不接受负数、布尔值和越界整数。

| 接口 | 输入 | 返回 |
|---|---|---|
| `encrypt_block(plaintext, key)` | 两个 16 bit int | 16 bit 密文 int |
| `decrypt_block(ciphertext, key)` | 两个 16 bit int | 16 bit 明文 int |
| `expand_key(key)` | 16 bit int | `(K0,K1,K2)`，每项 16 bit |
| `encrypt_trace(plaintext,key)` | 与加密相同 | `CipherTrace` |
| `decrypt_trace(ciphertext,key)` | 与解密相同 | `CipherTrace` |
| `block_to_state(block)` | 16 bit int | `((s00,s01),(s10,s11))` |
| `gf_mul(left,right)` | 两个 4 bit int | 4 bit 乘积 |
| `sub_nibbles(block,inverse=False)` | 16 bit 状态 | 替代后的状态 |
| `shift_rows(block)` | 16 bit 状态 | 第二行交换后的状态 |
| `mix_columns(block,inverse=False)` | 16 bit 状态 | 混淆后的状态 |

`CipherTrace` 含 `output`、`round_keys`、`steps`。`steps` 为九个 `TraceStep(name,state)`：输入状态加八次变换。

```python
from saes import encrypt_block, decrypt_block, expand_key, encrypt_trace

assert expand_key(0x2D55) == (0x2D55, 0xBCE9, 0xA34A)
assert encrypt_block(0x6F6B, 0xA73B) == 0x0738
assert decrypt_block(0x0738, 0xA73B) == 0x6F6B
for step in encrypt_trace(0x6F6B, 0xA73B).steps:
    print(step.name, f"{step.state:04X}")
```

核心使用整数保存状态，以减少攻击搜索时的对象分配。乘常数 2、4、9 的表由同一有限域乘法生成。普通加解密不构建追踪对象，只有 GUI 请求过程时才生成步骤。

## 3. 编码与密文包

| 接口 | 说明 |
|---|---|
| `parse_number(text,bits=16)` | hex/二进制解析，bits 可选 16/32/48 |
| `format_bits(value,bits=16)` | 保留前导零，每四位空格分隔 |
| `bytes_to_blocks(data)` | 大端两字节分组，返回 `(blocks,original_length)` |
| `ascii_to_blocks(text)` | 严格 ASCII 编码后分组 |
| `blocks_to_bytes(blocks,original_length=None)` | 若传原长度则精确截断，不用 rstrip 去零 |
| `escape_bytes(data)` | 可打印字符保留，其余显示 `\xHH`，反斜杠也转义 |

`CipherPacket(mode,blocks,original_length,iv=None)` 是不可变数据类。`blocks` 为 tuple，分组 16 bit；mode 为 ECB/CBC。CBC 必须有 16 bit IV，ECB 不允许 IV。分组数量必须是 `ceil(original_length/2)`。

```python
from saes.modes import CipherPacket, decrypt_packet, encrypt_ascii

packet = encrypt_ascii("ABC\n", 0xA73B, "CBC", 0x1357)
serialized = packet.to_json()
restored = CipherPacket.from_json(serialized)
assert decrypt_packet(restored, 0xA73B) == b"ABC\n"
```

`encrypt_ascii(text,key,mode='ECB',iv=None)` 生成包。CBC 不指定 IV 时使用 `secrets.randbits(16)`。`decrypt_packet(packet,key)` 返回 bytes，使错误密钥或篡改后的非 ASCII 字节也能保留；界面普通解密额外尝试严格 ASCII 解码，篡改对比直接转义显示字节。

JSON 字段：`version=1`、`profile='S-AES-AppendixD-v1'`、`mode`、`encoding='ascii'`、`padding='zero-with-length'`、`original_length`、`iv`、`blocks`。分组及 IV 采用四位 hex 字符串，IV 在 ECB 时为 null。包中不包含密钥。导入时验证版本、参数配置、类型、数量和位宽。

原始长度是自定义协议元数据。零填充本身无法区分“原有末尾零”和“填充零”，因此必须携带长度；协议没有认证这个元数据，也不提供密钥正确性或完整性的保证。

## 4. 多重模式与攻击

```python
from saes.multiple import double_encrypt, double_decrypt, triple_encrypt, triple_decrypt
from saes.attacks import meet_in_the_middle

key = 0x1F2E3D4C
pairs = [(p, double_encrypt(p, key)) for p in (0x6F6B, 0x1234, 0xBEEF)]
assert meet_in_the_middle(pairs) == [key]
assert triple_decrypt(triple_encrypt(0x1234, 0x00001F2E3D4C, 48),
                      0x00001F2E3D4C, 48) == 0x1234
```

双重接口固定使用 32 bit K1||K2。`triple_encrypt/decrypt(block,key,bits=48)` 显式选择 32/48 bit，不通过数值大小推断模式；32 bit 采用 K1-K2-K1 的 EEE。

`meet_in_the_middle(pairs,progress=None,cancel=None)`：

1. 使用第一组 `(P,C)`，枚举所有 K1，建立 `E_K1(P) -> [K1,...]` 字典。
2. 枚举所有 K2，计算 `D_K2(C)`，查找所有相同中间值。
3. 对每个候选 K1||K2 用额外所有已知对过滤，返回完整候选列表。

首对建表与匹配的时间和空间均约为 O(2^16)；额外验证的成本还取决于候选数与已知对数。分组只有 16 bit，单对通常留下约 2^16 个组合密钥，不保证唯一。不能覆盖碰撞的 K1，也不能只返回首个命中。

progress 是可选回调 `(stage,done,total)`，两个阶段的 total 均为 65536。cancel 为可选 `threading.Event`，每 512 个枚举项检查一次；取消抛出 `AttackCancelled`。提供相互矛盾的已知对时返回空列表。

## 5. GUI 线程与错误处理

Qt 控件只在主线程访问。中间相遇计算运行于 daemon 线程，通过 `queue.Queue` 回传进度、结果或错误；主线程用 `QTimer` 轮询，取消时设置 Event。关闭窗口也设置取消事件。

导入 JSON 不依赖“此前是否在本窗口加密”，因此接收方可以在新会话直接解密。CBC 解密与对比以包内 IV 为准。篡改实验复制分组数组后运算，不修改原密文包。

`WorkspaceUI` 构建五页布局，`QStackedWidget` 与 `QScrollArea` 管理页面和小窗口滚动；`Card`、`NavButton`、`StateMatrix`、`BinaryStrip` 等组件统一样式。图标由抗锯齿 QPainter 绘制，不分发外部字体或图标包。最小窗口为 1060×720 逻辑像素，各页可纵向滚动访问。

2.0 通过 QButtonGroup 筛选原始九步追踪，不重算或改变算法。上一步/下一步只访问未隐藏的行；矩阵与完整追踪中的上一状态比较，计算半字节差异及 XOR 的 bit_count。编辑输入会使结果标记为待更新并禁用复制、回填；成功运算后恢复。JSON 语法高亮只设置文本格式，文件内容和协议不变。桌面版本集中在 version.py，与密文 profile 独立。

## 6. 验证与维护

`tests/test_saes.py` 为标准库 unittest；`tests/reference_saes.cpp` 用独立数组状态与多项式乘法实现互测。C++ 不调用 Python、不硬编码完整结果。`tools/verify.py` 从固定随机种子生成样本，实际调用 C++ 子进程，逐条核对两方向与任意密文解密，并生成 CSV 和五关报告。

`tools/gui_smoke.py --offscreen` 使用 Qt 自身的鼠标/键盘测试事件与真实回调，覆盖加解密、矩阵联动、编辑提示、跨窗口文件导入导出、错误向量、取消、IV、篡改与小窗口。日志记录框架及版本；`--render` 仅把本程序离屏渲染到忽略的 `build/gui-qa/render` 用于布局检查。实际桌面操作的 15 张原图保存在根目录“截图与视频”，对应步骤见 [截图说明](截图说明.md)。

`tools/check_repository.py` 检查 Markdown 本地链接、15 张必需截图和交付文件；`tools/package_release.py` 按固定目录清单生成 ZIP，排除虚拟环境、归档、缓存、构建产物和 Office 锁文件。目录职责及移动记录见 [仓库整理说明](仓库整理说明.md)。

修改核心参数时，应先核对课程 PDF，再更新标准文档、固定期望和交换协议 profile。修改视觉布局时，运行 GUI 检查并更新截图。不要仅通过“自身加密再自身解密”声称符合算法标准。
