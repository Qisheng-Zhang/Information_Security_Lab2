# 用户指南

## 1. 启动与通用规则

Windows 双击 `启动程序.bat`，首次会在项目 `.venv` 中安装 Qt 依赖，随后打开 **S-AES Studio 2.2**。手动启动请先执行 README 中的环境安装命令，再用 `.venv\Scripts\python app.py`。使用左侧五个导航入口切换关卡，每页输入独立保存。

16 bit 输入支持 `A73B`、`0xA73B`、`1010011100111011`、`1010 0111 0011 1011`。空白和下划线会被忽略。完整 16 位 01 串按二进制解释，其余无前缀输入按十六进制解释：`10` 表示十六进制 `0010`；二进制 2 应输入小写前缀 `0b10`。32/48 bit 密钥采用同样规则。大写 `0B01` 是合法 HEX 分组，不当作二进制；要输入小写的同一 hex 值可写 `0x0b01`。

非法字符、负数、超出位宽或空输入均提示错误，不会静默截断高位。

## 2. 基本加解密

1. 选择“基本加解密”。输入分组 `6F6B` 和密钥 `A73B`。
2. 点击“加密”，右侧结果应为 `0738`；下方显示 K0、K1、K2 和每步状态。
3. 点击结果卡的“回填”，输入变为 `0738`；再点“解密”，应恢复 `6F6B`。
4. “复制”复制完整 HEX 结果，保留前导零。“随机”同时更换输入分组与密钥。

点选任一轮状态，右侧四格矩阵会同步显示半字节值；着色单元格表示与上一变换结果不同，Δ 显示变化的 bit 数。悬停单元格可查看坐标、HEX 与四位二进制。矩阵按列优先映射。第二轮不包含列混淆。小窗口中可滚动查看全部九个状态（含输入）。

结果区右上角的 4×4 小方格对应结果的 16 个 bit，由左上向右下按最高位到最低位排列。点击复制后，按钮短暂显示“已复制”；输入修改或重新运算会撤销旧反馈。

状态表上方可切换“全部步骤 / 初始轮 / 第 1 轮 / 第 2 轮”。上一步、下一步仅在当前筛选范围内移动，也可使用 `Alt+← / Alt+→`。基本页中 `Ctrl+Enter` 加密，`Ctrl+Shift+Enter` 解密。

修改输入后，结果卡提示“请重新运算”，旧结果的复制和回填暂时禁用；重新运算成功后恢复。非法字段会标记为红色，修正并运算成功后清除标记。

## 3. 交叉测试

“生成向量”生成含边界值和随机值的 JSON，点击“导出”后交给另一个实现的使用者。对方必须独立加密并解密验证。

收到对方文件后，“导入对方文件”把它加载到左侧，也可直接粘贴；点击“开始验证”，右侧逐行比较：

- 本组加密是否等于对方密文。
- 本组解密对方密文是否恢复对方明文。

生成后立即验证自己的文件只是自检，不能算另一小组的现场交叉测试。已附的 Python/C++ 自动互测是在本机两个独立实现之间执行，真实小组信息应记录到单独模板。

交换格式示例：

```json
{
  "profile": "S-AES-AppendixD-v1",
  "vectors": [
    {"plaintext": "6F6B", "key": "A73B", "ciphertext": "0738"}
  ]
}
```

## 4. ASCII 字符串

1. 在左侧填写密钥及英文、数字、符号或换行，例如 `Hello, S-AES!`。
2. “加密”生成右侧 JSON，底部预览实际密文字节，不会把密文再次解密后冒充密文显示。
3. “导出”保存密文包。接收方启动程序，填同一密钥、导入包，再“解密”即可还原，无需先执行加密。

中文不在本关 ASCII 编码范围，会得到清楚的输入提示。每两字节一个分组，高字节在前；奇数长度只补一个 `00`。包中 `original_length` 保存原始字节数，因此空串、末尾空字节、末尾换行可准确恢复。

密文字节可能超过 `7F`，不能保证本身是有效 ASCII。界面保留可打印字符，其余显示为 `\xHH`；例如字节 `FF` 显示为 `\xFF`。可交换数据始终以 JSON 内的 hex 分组为准，不能把预览字符串直接当明文粘贴解密。

输入区下方实时显示字节数、分组数；奇数长度会提示补一个字节。换行计入实际字节数。JSON 的颜色只用于区分字段和值，不修改可导出的文本。

## 5. 多重加密与攻击

选择模式后，输入对应位宽的组合密钥：

| 模式 | 示例密钥 | 顺序 |
|---|---|---|
| 双重 / 32 bit | `1F2E3D4C` | 先 K1 后 K2 的 EE |
| 三重 / 48 bit | `1F2E3D4C5A6B` | 先 K1、再 K2、再 K3 的 EEE |
| 三重 / 32 bit | `1F2E3D4C` | K1、K2、K1 的 EEE |

三重模式是 EEE，不是 3DES 的 EDE。模式由下拉框显式决定；48 bit 密钥 `00001F2E3D4C` 的第一段 K1 为零，仍按三段密钥处理。

中间相遇区独立针对**双重**加密。每行输入一个 `明文 密文` 对，均为四位 hex。点击“载入示例”可载入 K=`1F2E3D4C` 产生的三组已知对：

```text
6F6B FE80
1234 69D8
BEEF 093D
```

“开始完整搜索”枚举完整 K1、K2 空间。单对常有大量碰撞；三对示例可唯一留下 `1F2E3D4C`。搜索期间可切换页面或取消。超过 100 个候选时界面只预览前 100 个，“导出候选”保存全部候选。结果为零表示没有密钥满足所有输入对；多个候选时应增加不同明文的已知对。

## 6. CBC 与篡改实验

1. 输入密钥和 ASCII 消息。点击“随机 IV”，或手工输入 `1357` 以复现实验。
2. 点击“加密”，右侧密文包会携带 IV，接收方导入后即可共享这个值。
3. 解密时以**包内 IV**为准，左侧 IV 自动同步。解密不会使用意外留在输入栏中的其他 IV。
4. 在篡改区指定分组编号（从 1 起）。“异或翻转”把输入值当作 XOR 掩码；`0001` 翻转最低位。“替换分组”把指定分组整个替换成输入值。
5. 点击“对比解密”，对照原明文、篡改后明文和逐组 XOR 差值。原包保持不变，可重复实验。

修改 Ci 通常使 Pi 的多个位发生变化，并使 P(i+1) 出现与 Ci 修改差值相同的位翻转；更后面的分组保持不变。最后一个密文分组没有后继分组。修改 IV 则只按同样 XOR 差值改变第一个明文分组。

空消息可以正常加解密，但没有可供篡改的分组。IV 由 `secrets.randbits(16)` 生成；固定 IV 适合复现实验，正常使用应为新消息重新随机生成。CBC 不包含消息认证，不能仅凭解密“看起来正常”判断密文未被修改。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 提示没有 PySide6 | 双击新版启动脚本安装依赖，或执行 `.venv\Scripts\python -m pip install -r requirements.txt` |
| 仍看到旧版窗口 | 关闭之前打开的程序，从新版目录运行启动脚本；当前标题为 S-AES Studio |
| `1234` 被当成 hex | 这是明确约定；用 `0b` 指定短二进制输入 |
| 解密后含非 ASCII 字节 | 检查密钥、算法参数及密文包是否被修改 |
| 与旧 C++ 程序密文不同 | 核对 S 盒和第二轮常量；该历史版本与所给 PDF 不同 |
| 互测显示多个失败 | 先比较 `2D55` 的轮密钥，再比较状态位序、S 盒与列混淆 |
| 攻击恢复多个密钥 | 增加不同明文的明密文对；不要直接把第一个候选当真密钥 |
